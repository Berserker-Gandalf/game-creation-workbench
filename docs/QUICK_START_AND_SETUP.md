# 第一次使用与工具装配

适用版本：0.19.0。日期：2026-10-28。推荐Windows，本机单用户。

> 0.19 推荐入口：下载自带 Python 的 Windows 安装包或 ZIP，打开 ZAOWU.exe 即可管理项目；无需先装基础组件。系统目录选择、SUNO 原包装配、WebUI 硬件预检详见[应用与装配指南](WINDOWS_APP_AND_SETUP.md)。下方源码装配步骤继续保留。

## 1. 不配置AI，也能先开始

1. 使用包含预构建界面的发布候选ZIP，解压到可写文件夹。不要直接在压缩包内运行。
2. 双击根目录的`Install-Workbench.cmd`。已有兼容Python时建立本地运行环境；缺少Python时，引导通过Windows程序管理器安装Python 3.12，需要本人确认。没有WinGet时会给出Python官方安装入口，完成后重新打开即可。
3. 基础依赖准备后自动启动浏览器。预构建界面的版本和逐文件哈希匹配时，**核心项目管理无需安装Node/npm，也不重新构建前端**。
4. 首次空白工作台自动打开“快速上手”。选择“项目管理”即可继续第三步，点击“创建或打开练习项目”。
5. 在总览修改项目总纲，打开“设计资料”和“任务看板”，记录第一项修改。练习项目只有说明文档和待执行任务，不调用模型、不消耗积分，也不是已经创建好的Unreal/Unity游戏工程。

已有真实游戏时，改用“接入我的已有游戏”，继续原有目录接入流程。练习项目重复点击只打开同一个项目，不重复创建。已有项目的老用户不会被强制重新走向导。

## 2. 按需要启用功能

左侧“快速上手”分为检查基础、选择与装配、开始创作。可以先使用核心管理，之后再启用创作工具。

| 选择 | 自动处理范围 | 仍由用户完成 |
| --- | --- | --- |
| 项目管理 | 基础依赖、发布界面校验、练习项目 | 填写自己的设计与验收依据 |
| Codex会员 | 发现现有入口；缺少时先装Node，再将固定版本Codex装到当前数据目录的`tools/npm` | 在官方页面登录，选择账号可用模型并核验连接 |
| OpenAI/DeepSeek API | 打开连接设置与官方Key入口，无需本机模型 | 使用自己的Key、模型及额度，实际联调 |
| Suno.cn音乐 | 可装配Node，提供供应方Skill指引和可交给Agent的安装请求 | 原版Skill安装、本人网页授权及付费生成确认 |
| Blender | 发现现有程序；缺少时通过WinGet安装 | 在建模页验证路径/版本，审阅并生成独立草稿 |
| Tripo | 打开建模连接设置与服务入口，无需本机3D模型 | Key/区域/额度设置，审阅图像上传与积分消耗 |
| WebUI绘画 | 打开已有安装的配置和官方安装指引 | GPU环境、模型/LoRA选择与下载、启用本机API |
| GitHub项目发布 | 发现或通过WinGet安装Git | 创建仓库、配置凭据与素材权利，审阅上传 |
| Unreal/Unity | 打开连接设置及官方安装入口 | 引擎版本、许可、工程和连接器安装确认 |

选择功能不会授予Agent权限或购买服务。Codex与音乐的Node是可选功能依赖，不是预构建工作台核心界面的前置条件。

## 3. 查看清单后装配

在第二步选择功能，点击“查看装配清单”。工作台只列缺少的支持工具，已有程序跳过；不会自动升级既有安装。

确认工具、来源和安装范围后点击“按此清单装配”。Node/Git/Blender使用WinGet固定包标识；Codex使用官方npm包`@openai/codex@0.163.0`，安装在当前工作台数据目录，保持本机全局Codex。该版本是本轮本机协议核对所用版本，不声称永远最新。

安装需要网络及磁盘，系统可能显示权限提示。来源协议、软件许可与管理员确认需要本人处理；工作台不传自动接受协议参数。若WinGet要求在交互窗口完成来源协议，或受组织策略限制，可改用页面中的官方安装入口，再回来点击“重新检测工具”。

装配记录区显示进行中、失败或待核对；详细安装输出保留在当前数据目录`logs/setup.<编号>.log`，界面只展示位置，不把完整日志送给模型。首次检查只发现文件，不查余额、不发生成请求。安装器返回成功也只表示命令结束，仍需到对应工作区验证连接和实际产出。

正在装配时正常停止接口会要求等待；不要用强制结束工作台来取消系统安装器。若进程中断或等待超时，记录为待核对，不自动重放安装。先确认系统安装器结束，再点“确认安装器结束并重新检测”；未安装齐时可以重新预览，由本人再次发起。

## 4. 常见卡点

| 遇到的问题 | 处理方式 |
| --- | --- |
| 下载源码后缺少Python | 双击Install入口，按窗口指引确认安装；没有WinGet时使用窗口提供的Python官方入口 |
| 想避免前端编译和Node安装 | 使用带`dist/`及`workbench-build.json`的发布候选ZIP；GitHub的Code源码ZIP通常需要构建 |
| 程序找到了但不能登录或生成 | “已发现”只是文件状态，到对应工作区做连接核验；账号/网络/模型/许可分别处理 |
| 基础依赖安装失败 | 保留错误窗口，检查网络；先正常停止工作台，再运行`Repair-Workbench.cmd`。它重装基础依赖，不删除数据 |
| 界面缺文件或版本不匹配 | 运行Install或Repair入口会校验发布界面；必要时构建源码，缺少Node时再引导安装 |
| 修改源码后需要重新构建 | 开发者运行`./scripts/Setup.ps1 -RebuildUI`，或依赖已就绪时运行`npm run build` |
| 安装器结果未知 | 先核对系统安装器和本机日志，再人工确认结束；不重复点击原提交 |
| 网页关闭了，服务还在运行 | 使用Stop-Workbench正常停止，数据目录继续保留 |

只想检查，不想安装时可运行：

```powershell
./scripts/Setup.ps1 -CheckOnly
```

它返回是否找到Python、基础依赖是否就绪、预构建界面是否匹配及是否需要Node，不建立虚拟环境、不安装依赖、不创建工作台数据库。已有运行环境仍使用原启动入口；轻量Python宿主不因本版向导而强制依赖前端源码包。

## 5. 接口与安全范围

向导接口位于`/api/onboarding`，预览、安装和练习项目分别使用`/plan`、`/install`和`/practice`。安装预览10分钟有效、一次使用；请求只接受固定工具标识，不接受任意命令、下载地址或安装目录。后台串行装配，依赖失败立即停止；启动恢复只标记待核对，不恢复安装执行。安装能力没有加入Agent业务动作目录，原76项动作与21项工具名称保持。

功能选择与查看状态保存在当前本机数据库，不作为项目恢复时的权限继承。练习项目由固定内容生成，默认未验收；向导不会改已有游戏文件或授予全功能、整机及自动积分权限。

构建生成`dist/workbench-build.json`，记录界面版本和逐文件SHA-256。PowerShell用本身可用的.NET完成哈希，不依赖Node、Python或额外哈希命令来判断预构建界面是否可复用。哈希校验是完整性检查，不等于已签名安装器。

接口依据：[WinGet安装说明](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)、[Codex CLI官方说明](https://learn.chatgpt.com/docs/codex/cli)、[供应方Suno Skill说明](https://mcp.suno.cn/mcp/skill/setup.md)。系统包标识来源为Microsoft维护的WinGet仓库；实际可用版本、许可和下载以服务端为准。

## 6. 本轮验证与后续改进

验证范围包括固定工具清单与依赖顺序、确认/过期/防重复、失败停止、重启未知状态、不继承权限、练习项目幂等，以及Windows原生PowerShell在没有Python/Node的模拟环境中识别预构建界面和损坏文件。浏览器使用自制数据和模拟安装器，检查首次引导、功能选择、装配预览/完成、官方指引和免费练习项目。没有在用户电脑实际安装或升级软件，也没有新的模型、付费生成或引擎运行验收。具体测试数见[本轮记录](verification/onboarding-v0.18.json)。

0.19 已完成自带 Python 的安装候选、系统目录选择、原版 SUNO Skill 固定哈希装配及 WebUI 硬件预检，见[本版指南](WINDOWS_APP_AND_SETUP.md)。仍待干净 Windows 虚拟机、代码签名、自动升级/数据库回滚、脱敏支持包和首次创作全流程教程。GPU 权重与引擎不自动装配，真实收费生成保持独立授权与验收。
