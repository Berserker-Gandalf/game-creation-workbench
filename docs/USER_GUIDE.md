## 1. 产品定位

**游织工坊是运行在个人电脑上的游戏创作 AI 工作台。** 它把游戏设计讨论、项目资料、任务、资产和执行记录放在同一个工作空间中，项目可选择 Unreal Engine 或 Unity。

你可以让项目负责人理解设计、起草文档、拆解任务、查看图片、整理进度；切换音乐负责人保存配乐方案，或让建模负责人设计 Blender/Tripo 方案。生成和收费操作按对应工作区审阅确认。项目管理还包括设计变更复核、资产版本、账户额度、工程快照和 GitHub 留存。

本版适合个人创作和受控试用。目前仍需要创作者判断设计取舍、确认收费操作、验收内容，并在引擎中验证实际效果。尚不能把一段需求自动转成经过完整验收并可发布的游戏。

### 功能与验收范围

| --- | --- | --- |
| 项目管理 | 新建项目、选择引擎、保存项目总纲、绑定已有工程 | 留空工程路径时只是资料工作区，不会创建完整引擎工程 |

| Blender 角色建模 | 参数化低模方案、固定本机生成、可编辑源文件/GLB/预览、派生版本 | 已有独立三模板实测；不提供自动雕刻、骨骼绑定或动画 |
| Tripo 建模 | 文生/图生方案、区域/积分、确认提交、查询与 GLB 纳入资产 | 模拟验证通过；真实积分和付费生成待验收 |
| 音频与模型 | 音频试听、16 位 PCM WAV 裁剪/短淡入淡出、GLB 查看 | 不能编辑模型网格、骨骼或动画 |
| 引擎连接 | 扫描资产、读取属性、部分预览、已有材质颜色参数修改 | Unreal 4.27.2 有历史运行验收；Unity 仅编译通过，运行待验收 |

| MCP 与执行记录 | 角色工具目录、运行时隔离核验、模型/用量/调用摘要、停止对话 | 暂不提供任意外部 MCP 服务器注册或自动收费任务重放 |
| 账户额度 | Codex 窗口、Suno/Tripo 积分、DeepSeek 余额、查询时间与过期标记 | Codex/Suno 已有只读实测；其他余额待真实联调；OpenAI API 现金余额未接入 |
| 工程快照 | 过滤工程文件和工作台资料、命名与父链、SHA-256 校验、独立目录恢复 | 要先保存并暂停写入；不包含被排除缓存、外部链接目标，不是文件系统原子快照 |
| GitHub 留存 | 冻结快照的文件审阅、独立新分支、Git LFS、结果核对 | 需 Git/仓库/Token；本地隔离推送测试通过，真实 GitHub 上传待联调 |
| 资料备份 | 格式 10 ZIP 保留已登记资产版本、文档/任务/会话与副本恢复 | 不是完整游戏工程备份；不含密钥和浏览器未提交草稿 |

本轮重新核验为 **202 项自动测试通过、生产构建通过**；这些结果不能代替真实 API、实际游玩或所有引擎版本的验收。供应商/引擎的实测是独立历史记录，本轮没有重新发起真实调用。详见 [开发状态](DEVELOPMENT_STATUS.md) 和 [0.15读取验证](verification/bounded-reads-v0.15.json)。

## 2. 安装与启动

### 2.1 首次使用

推荐解压带预构建界面的发布候选后双击`Install-Workbench.cmd`，按窗口准备基础环境，再进入“快速上手”。匹配预构建界面时核心管理不需要Node；缺少Python时提供WinGet装配或官方安装指引。可以先创建免费练习项目，再按需要选择创作工具。完整操作见[首次使用与工具装配](QUICK_START_AND_SETUP.md)。

下列保留开发者手动路线：Windows源码构建建议Python 3.12、Node.js 24与npm。Codex、音乐、建模等可在向导中按需装配或查看指引，账号授权由本人完成。

本机已经配置好的依赖无需重复安装。新电脑首次使用，在项目根目录的 PowerShell 中执行：

```powershell
./scripts/Setup.ps1
```

安装过程需要联网。启动工作台本身不会自动发起图片或音乐生成。

### 2.2 一键启动

1. 双击根目录的 `Start-Workbench.cmd`。
2. 等待安装或构建完成，浏览器打开 [本地工作台](http://127.0.0.1:8765)。
3. 完成使用后，双击 `Stop-Workbench.cmd` 停止服务。

不要只关闭浏览器后就认为服务已经停止。正常数据默认保存在项目目录的 `.workbench/`，更新源码时应保留它。

0.18发布包附带界面版本与哈希清单；Setup校验匹配后跳过npm，仍需要Python及后端依赖。Install入口能引导基础准备，Repair入口可在停止服务后重装基础依赖；不会删除数据。没有私有Python运行时，也不是独立安装器。第2.4节的手动入口继续保留。

### 2.3 使用 VS Code 的 F5 入口

1. 用 VS Code 打开 **Game_API 项目根目录**，不要只打开某个 Python 文件。
2. 安装推荐的 Python 和 Python Debugger 扩展；首次安装项目依赖时先完成上面的环境准备。
3. 在“运行和调试”中选择 **工作台：运行与调试**。
4. 按 **F5**。配置会先构建界面，再启动后端，服务就绪后打开浏览器。
5. 后端可设置 Python 断点；日志同时输出到集成终端和调试控制台。
6. 按 **Shift+F5** 停止。

一键启动与 F5 共用 8765 端口，请选择一种启动方式。此配置调试 Python 后端，不包含浏览器中的 TypeScript 断点。

前端开发需要热更新时，可以在后端运行期间另开一个集成终端执行：

```powershell
npm.cmd run dev
```

随后访问 [前端开发页面](http://127.0.0.1:5173)，其项目请求会转到 8765。修改普通源码并不会自动更新已经构建好的主页面，需要热更新页面或重新构建。

### 2.4 使用已构建 ZIP 的手动入口

仅适用于含 `dist/index.html` 的发布候选包。解压到可写目录，安装 Python 3.12 后，在解压根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -X utf8 -m backend.run
```

随后访问 [本地工作台](http://127.0.0.1:8765)。在启动终端按 Ctrl+C 正常停止。此入口不会调用 npm；安装后端依赖通常仍需联网。Codex、Suno、Git、Blender、WebUI 和引擎按所选功能单独配置，不能因为页面打开就视为这些工具已安装。

源码更新需要重新构建界面；不能长期用旧 `dist` 搭配新版后端。这种方式仍是浏览器工作台，不是已封装的桌面安装版。

## 3. 第一次使用：从空项目到第一份设计

以下过程可以先停在讨论和本地资料管理阶段，不需要提交收费图片或音乐生成。

1. 点击 **新建游戏项目**，填写名称并选择 Unreal Engine 或 Unity。
2. 如果只是整理想法，工程目录可以留空；如果要操作已有引擎资产，填写对应工程根目录。
3. 在 **项目总览 → 项目总纲** 写下游戏类型、核心体验、目标平台、风格与明确约束，点击 **保存总纲**。
4. 在 **模型与引擎** 连接一个对话服务。
5. 回到项目，在左侧会话中选择对应服务与模型，先保持 **讨论：只读工具**。
6. 发送需求，让 AI 梳理问题和设计方案。
7. 确认范围后再打开执行开关，请 AI 保存一份设计草稿或创建任务。
8. 到 **设计资料** 审阅草稿，修改后保存；你认可的版本再设为 **正式设计**。
9. 到 **任务看板** 填好交付与验收条件，关联设计版本和前置任务。
10. 在 **项目总览** 检查执行记录，保存编辑；有工程时进入 **项目留存** 保存检查点，按需另存资料包或审阅 GitHub 发布。

可以从下面这段需求开始：

> 我想做一个三间房的探索解谜原型，单人、无战斗、无昼夜系统。先用讨论模式整理核心循环、需要我决定的问题，以及一个小范围原型的验收标准，暂时不要保存文件。

## 5. 连接模型与理解费用

### 5.1 Codex 会员

1. 打开 **模型与引擎 → Codex 会员连接**。
2. 点击 **检查连接**，读取本机登录状态。
3. 需要登录时点击 **通过 ChatGPT 登录**，在官方页面完成流程，再重新检查。
4. 在对话区选择 **Codex · 会员**，使用“官方默认模型”或目录中的可用模型。

工作台使用本机官方 Codex App Server，身份由官方运行时管理。会员令牌不作为通用 API Key 使用，工作台也不会因此获得通用桌面鼠标键盘操作能力。

“已登录”只表示身份连接成功；实际推理、图片理解和具体工程操作仍要分别验证。使用过程受对应账号权限与额度限制。

### 5.2 OpenAI / DeepSeek API

1. 在对应服务卡片中填写 **API Key** 和 **文本模型 ID**，点击 **保存配置**。
2. 点击 **获取模型列表**，查看账号返回的模型目录。
3. 在对话区选择该服务，核对当前会话的模型 ID，再发送一个小范围请求。

模型列表可访问，不代表目录中的每个模型都已通过文本、工具或视觉验证。文本模型与图像模型分别配置；不同会话可以保存各自的服务和模型。

OpenAI 图片功能还需要填写 **图像模型 ID**。Codex 会员连接不能替代这里的独立 API 配置。本版已实现这两家的适配接口，真实 API 联调仍待完成；其他大模型供应商暂未提供可直接配置的界面入口。

### 5.3 费用按三个来源分别理解

| 操作 | 对应额度或计费来源 |
| --- | --- |
| Codex 会员对话、项目操作 | 对应 Codex / ChatGPT 账号额度 |
| OpenAI / DeepSeek API 对话及 OpenAI 图片生成/编辑 | 对应 API 服务的用量与计费 |
| Suno.cn 音乐生成 | Suno.cn 账号积分与服务规则 |

**讨论模式并不等于免费模式。** 它限制项目修改权限；对话仍会使用所选模型的额度。保存音乐方案本身不提交音乐生成，但 AI 讨论方案仍可能消耗对话额度。

图片生成按钮会直接提交请求，不要把它当成纯预览按钮。未授自动积分时，音乐生成有单独的方案确认和积分确认。工作台记录可取得的 usage，但没有精确金额预算或供应商账单核对能力。

## 6. 与负责人交流、管理会话

### 6.1 讨论与执行

| 模式 | 适合做什么 |
| --- | --- |
| 讨论：只读工具 | 读取已有资料，分析玩法、资产和状态，提出建议 |
| 执行：允许本轮修改 | 使用当前角色已开放的写工具，保存设计草稿、创建任务或保存音乐方案等 |

项目负责人使用 Codex 的执行模式时，还允许其通过项目工具在所选工程内操作文件；音乐/建模默认关闭项目命令、只保存方案。0.10 可另行授予全功能、两家自动积分或 Codex 整机权限，详见第22节。

执行开关不是“一次勾选只生效一条消息”的自动关闭按钮：在当前会话组件中，后续发送仍会沿用当前开关。完成修改后请主动切回讨论，并在每次发送前核对模式。

建议先明确要修改的对象与验收结果，例如：

> 已确认三间房的探索方向。本轮开启执行：只保存一份《核心循环草稿》，再创建三个待执行任务，每项写明交付物和验收条件。不要修改现有正式文档，也不要提交图片或音乐生成。

### 6.2 会话操作

- 点击当前会话旁的 **＋** 新建会话，适合拆分玩法、美术和技术讨论。
- 展开 **会话设置与记忆**，修改名称或填写需要持续沿用的决定，点击 **保存设置** 才提交到项目。
- **复制会话** 会复制历史与已保存记忆，适合探索另一种设计方向；不会重放原来的工具或收费请求。
- **归档** 会保留历史并退出日常会话列表。勾选 **已归档** 查看，可取消归档或复制后继续。
- 在 **搜索会话记录** 中输入关键词，查找当前会话的历史；列表最多显示最近 100 条匹配记录，不表示其余记录已删除。

Enter 发送消息，Shift+Enter 换行。

### 6.3 记忆与正式设计如何配合

“会话记忆”适合保存已明确的约束或待解决的问题，例如：

> 已明确：单人探索、三间房、无战斗、无昼夜系统。第一版只验收探索与谜题循环；画风尚未定案。

记忆由你手动维护，不会自动成为正式设计。正式设计应保存在设计资料中，并明确状态。项目总纲提供整体方向，正式文档保存具体规则，会话记忆帮助延续当前讨论。

模型不会每轮读取无限长度的全部历史。工作台提供预算内历史、记忆和检索工具；较早的决定可以让 AI 按关键词检索。长文档会提供索引和片段，再由工具读取完整内容。

### 6.4 停止与核对结果

生成中点击输入框旁的方形停止按钮；也可以在最近的执行详情中停止运行中的对话。中断后已收到的部分回复会保留并标记未完整结束。

停止对话不等于撤销已执行的文件或资产修改，也不保证外部服务的生成任务被取消。请检查执行详情、资产版本和供应商结果，再决定下一步。

## 7. 管理设计资料

1. 打开 **设计资料**，选择 **新建文档** 或 **导入资料**，导入格式为 Markdown / TXT。
2. 填写标题和正文。正文可以使用 Markdown 写法，但当前编辑区主要是文本编辑。
3. 选择文档状态：**待定草稿**、**正式设计** 或 **已废弃**。
4. 点击 **保存新版本**，将修改提交到项目并生成版本记录。
5. 点击 **历史版本**，可以载入旧版内容进行比较或恢复；载入后仍需保存新版本才提交。

编辑时出现“有未提交修改”说明内容还没有写入项目版本。当前浏览器会尝试保存文档草稿；若提示保存失败，请先复制内容，避免清理浏览器或关闭页面后丢失。

如果项目文档已经产生新版本，旧编辑不能直接覆盖它。保留或复制草稿，对照项目新版本处理差异，再提交修改；刷新页面本身不会完成冲突合并。

## 8. 用任务看板管理进度

### 8.1 创建可验收任务

在 **任务看板** 填写任务名称、交付物与验收条件，点击 **添加任务**。也可以让开启执行的项目负责人创建。

| 不便验收的写法 | 更明确的写法 |
| --- | --- |
| 做好房间交互 | 三间房各有一个可触发交互点，在独立测试关卡中逐一触发并保存测试记录 |
| 完成配乐 | 保存探索场景候选音乐，试听确认无明显断裂，记录采用版本和适用场景 |
| 优化图片 | 保留原图，输出指定尺寸候选，检查主体未被意外改变并记录采用版本 |

### 8.2 状态与关联

常用状态为 **待执行 → 进行中 → 待验收 → 已完成**，另有 **受阻** 与 **已取消**。

点击任务的 **编辑与关联** 可以：

1. 修改名称和验收条件。
2. 勾选必须先完成的前置任务。
3. 选择作为依据的设计文档，保存时采用其当前版本。

前置任务未满足时，工作台会阻止依赖任务进入相应执行或验收状态。标记“已完成”必须填写验收依据，建议写出文件、版本和实际验证结果。

### 8.3 设计变化后的复核

关联文档更新、废弃，或者上游任务变化时，已有任务可能被标记为需要复核。历史完成依据保留，但过期验收不再计入当前已验收进度。

打开 **编辑与关联** 核对差异；确实采用新版设计时，点击 **确认采用当前设计，并重置为待执行**，然后重新交付和验收。上游任务重新完成不会自动替下游完成复核。

任务状态是项目管理记录。它不会单独启动引擎、安排独立执行者或证明游戏已经可玩。

## 9. 查看与编辑游戏资产

### 9.1 导入与查找

在 **资产工作区** 点击 **导入资产**，或绑定工程后点击 **扫描工程**。可以按图片、音频、3D、引擎类型筛选并搜索名称。

常见入口格式包括 PNG/JPG/WebP/GIF、WAV/MP3/OGG、GLB，以及已支持的原生引擎文件。上传大小受 60 MB 请求上限约束，请准备较小文件。能导入或登记文件，不代表该类型能够直接在浏览器中编辑。

### 9.2 图片查看与本地编辑

1. 点击图片，查看尺寸、大小和版本记录。
2. 修改宽高后点击 **保存尺寸修改**；或选择 **水平翻转并保存**。
3. 点击 **版本记录** 中的项目切换版本，或者下载当前文件。
4. 需要 AI 分析时点击 **交给 AI 查看**，返回左侧输入具体问题并发送。

图片预览与尺寸/翻转操作本身不调用生成模型。AI 查看会使用所选模型的相关能力和额度。文件编辑会保存新版本，原始文件保留；若版本发生变化，需要重新读取后再修改。

### 9.3 AI 美术生成与编辑

在“绘画来源”选择 OpenAI 或本机 WebUI。OpenAI 需先配置 Key 与图像模型；WebUI 需在管理页保存目录、启用 API 并选择可用模型。详细参数与使用步骤见 [WebUI 指南](WEBUI_GUIDE.md)。

以下为通用操作入口：

- **新图生成：**在“美术创作”中输入场景、用途、风格和构图，点击 **生成一张候选**。
- **参考图编辑：**在图片详情填写修改需求，点击 **生成编辑候选并保存**。
- **局部编辑建议：**先导入与原图同尺寸、包含完全透明区域的 PNG，在 **局部编辑遮罩** 中选择它，再提交编辑。

建议明确保留内容：

> 用作探索游戏的房间概念图。保留中心门洞和左右动线，只调整墙面材质与冷暖光分布，避免新增角色。

OpenAI 来源会调用独立 API 并可能计费；WebUI 来源使用本机 GPU。遮罩表达编辑建议，不能保证边缘或非透明区域完全不变；生成后的候选仍需人工检查。OpenAI 来源没有任意分辨率控制；WebUI 来源可设置宽高、步数、CFG、Seed、LoRA 与重绘幅度。本版一次生成一张，OpenAI 真实联调仍待完成。

### 9.4 音频和 3D

音频可在详情中试听。裁剪功能限 **16 位 PCM WAV**：输入起点与终点，点击 **裁剪并加入短淡入淡出**，再试听并核对新版本。MP3/OGG 的导入与试听不表示支持直接裁剪。

GLB 可在浏览器中旋转、缩放查看，建议使用资源自包含的文件。FBX 等文件不等同于 GLB 浏览器查看器；模型网格、材质节点、骨骼和动画仍需要相应引擎或专业工具处理。

## 10. 使用音乐负责人和 Suno.cn

### 10.1 角色与工具的关系

音乐负责人由你在左侧选择的 Codex / OpenAI / DeepSeek 模型驱动。Suno.cn Skill 提供音乐执行能力，本身不是另一个聊天模型。

该角色主要处理音乐需求、风格、方案及结果状态，可以保存待确认的音乐方案、设计草稿和任务；不能操作引擎或修改图片，也不直接获得收费提交工具。

### 10.2 授权

1. 确保本机已安装原版 `suno-cn-music` Skill 及 Node.js，安装方法见 [音乐 Skill 说明](SUNO_CN_SKILL.md)。
2. 进入 **音乐工作区**，点击 **登录授权 / 核验账户**。
3. 如果出现授权入口，由你打开服务页面完成登录与批准。
4. 回到工作台再次核验，以界面显示的授权结果为准。

凭据由原版 Skill 管理，工作台不复制其凭据文件。该流程使用 Suno.cn 账号与积分；不能推定它与其他 SUNO 网站的账号或权益互通。

### 10.3 从方案到结果

1. 先与音乐负责人讨论名称、用途、风格、创作描述和是否纯音乐。
2. 开启执行，让 AI 保存方案；或者直接在右侧填写并点击 **保存待确认方案**。
3. 审阅方案，确认确实要生成后点击 **确认方案并提交生成（消耗积分）**，阅读并确认弹窗。
4. 有远端编号的记录可以点击 **查询服务端结果**，手动取得进度。
5. 结果返回后打开音频试听，按供应方提供的方式下载，再导入工作台资产区。
6. 在项目任务中记录采用文件与验收依据；“生成完成”不等于已被项目采用。

可以这样提出一个尚不提交生成的需求：

> 先读取当前正式设计，为安静的探索房间整理一份纯音乐方案：低密度、无鼓点、避免强烈情绪起伏。先给出名称、风格和创作描述，暂不保存或提交生成。

本版仅开放基础描述生成表单，不提供精确时长、逐字歌词、自定义高级模式、翻唱、续写或分轨编辑流程。

### 10.4 结果未知时

遇到“结果待核对”“积分不足”或提交中断，先核对 Suno.cn 的作品和任务，不要反复提交。同一份已提交记录不会因为刷新而自动再次收费。

已有远端编号时可手动查询；没有编号的未知请求不能假装已自动恢复。积分补充后的供应方恢复流程需要另行核对，当前工作台没有自动购买或恢复按钮。

## 11. 连接 Unreal Engine 或 Unity

### 11.1 连接前的准备

先备份工程，并优先用独立测试工程熟悉操作。安装连接器会写入所选引擎工程；仅在资料工作区中新建项目不会自动建立这些连接。

| 引擎 | 应选择的目录 | 已有验收范围 |
| --- | --- | --- |
| Unreal Engine | 包含 `.uproject` 的工程根目录 | Unreal 4.27.2 的部分贴图、材质、预览、保存与重开读回已有独立实测 |
| Unity | 包含 `ProjectSettings/ProjectVersion.txt` 的工程根目录 | Unity 6000.5.3f1 连接器独立编译通过；运行与实际保存待验收 |

不要把引擎安装目录当作游戏工程目录。

### 11.2 操作顺序

1. 在创建工作台项目时绑定已有工程目录。
2. 关闭对应游戏编辑器。
3. 在 **模型与引擎** 点击 **安装到当前工程**，阅读并确认安装提示。
4. 重新打开引擎工程，等待插件或脚本编译完成。
5. 回到工作台点击 **验证编辑器连接**。
6. 到 **资产工作区** 点击 **扫描工程**。
7. 选择原生资产，按支持情况读取属性、获取预览或调整已有材质颜色参数。

材质修改需要填写资产中已经存在的参数名，点击 **备份并应用到引擎** 后，再到编辑器检查并保存验证。工作台会校验资产版本与目标位置；上传到资料区的原生文件副本不能直接当作工程内可写资产。

连接器只提供已实现的编辑器操作，不是任意蓝图、关卡、动画或 Shader Graph 编辑器。更多操作范围及卸载方法见 [引擎连接器说明](ENGINE_CONNECTORS.md)。

## 12. 查看进度、用量和 MCP 工具

### 12.1 执行记录

打开 **项目总览 → 最近执行记录**，展开 **执行详情**。较新的关联对话回复也有详情入口。

详情可查看服务、模型、运行状态、可取得的请求用量，以及工具调用的参数和结果摘要。记录可能出现 completed、failed、interrupted 等内部状态；分别表示本次执行结束、失败或中断，不等于整个游戏项目已经验收完成。

工具摘要会截短并过滤部分敏感字段，不是完整的终端录像。旧记录可能没有模型或工具信息；供应商不返回用量时也不能把它理解为零消耗。主界面仅展示最近一部分记录，不能据此认定旧数据被删除。

可以要求负责人按证据汇报：

> 请读取当前项目资料与任务，分别列出：已经保存的交付、等待人工验收的内容、受阻事项，以及下一步需要我决定的问题。不要把创建任务等同于完成任务。

### 12.2 MCP 工具目录

在 **模型与引擎 → MCP 工具与权限** 中选择负责人和讨论/执行模式，查看允许的工具。

点击 **核验运行时工具** 会检查本机 Codex 的实际工具目录，不发起模型推理。工作台会关闭继承的外部工具；自有桥不可用或实际目录与白名单不符时，阻止本轮模型启动。

工具目录核验、账号登录、真实推理、具体引擎操作是不同检查，某一个通过不代表其他项目全部通过。该页面也不是任意第三方 MCP 服务器的配置中心；Suno.cn 的授权和任务仍在音乐工作区管理。

## 13. 保存、备份与更新

### 13.1 哪些数据保存在哪里

| 数据 | 保存位置与特点 |
| --- | --- |
| 已提交的项目、文档、任务、消息及执行记录 | 默认在 `.workbench/`；更换 `WORKBENCH_DATA` 会切换为另一套数据 |
| 导入资产及资产编辑版本 | 保存在工作台数据目录或对应已绑定工程内；项目备份按已登记版本收集 |
| 未发送聊天、未提交文档、项目总纲及会话设置草稿 | 当前浏览器的本地存储；清理浏览器数据或换浏览器后不能依赖它恢复 |
| 游戏引擎工程 | 原工程目录；“项目留存”可保存过滤后文件集，外部依赖和被排除内容需另行留存 |
| 工程快照/发布记录 | 快照目录保存归档、清单、回执；索引与发布状态保存在本机数据库，格式 10 资料包不递归包含这些归档 |
| 服务凭据 | 本机配置或原版 Skill 自身管理；项目 ZIP 不导出 |

草稿保护不覆盖所有表单。任务新增框、音乐手填方案、美术生成需求等内容，请先保存或复制再切页。模型只能使用已提交的项目资料，不会自动读取尚未提交的浏览器编辑草稿。

### 13.2 导出与恢复

先确认留存目标：

| 目标 | 操作入口 | 恢复/使用方式 |
| --- | --- | --- |
| 工作台资料、会话、任务和登记资产版本 | 项目总览 → 导出备份 | 欢迎页“从备份恢复”，创建独立资料项目；名义上限 60 MiB 压缩包、500 MiB 解压量和 10,000 条目 |
| 当前工程文件和上述资料 | 项目留存 → 保存工程快照 | 校验后恢复至新目录；工程在 game/，资料包在 workbench/；资料包再次导入仍受上行限制 |
| 筛选后的 GitHub 共享/版本留存 | 项目留存 → GitHub 项目发布 | 独立快照分支；没有私有对话、完整历史和全部资产版本，不能替代完整快照 |

**导出：**先保存所有要保留的总纲、文档和方案，再到 **项目总览** 点击 **导出备份**。

**恢复：**在项目选择框中切回空的“选择项目”，进入欢迎页，点击 **从备份恢复** 并选择 ZIP。恢复会创建一个独立项目副本，不覆盖原项目。

格式10新增任务与创作方案的来源关联；格式9已增加资产交付、验收历史、音乐产出与队列历史；会保留 Tripo 任务及产出、已有工程接入清单与状态依据、角色建模方案、父版本与产出，以及创作参数记录，以及已提交的会话、记忆、设计与资产版本、任务关联、执行与工具记录；也兼容旧备份格式。恢复后的工具日志是历史快照，不会重放操作；音乐历史也不会自动重新提交。

恢复后的工程连接需要重新绑定处理，密钥和账号需要重新配置。当前界面没有直接修改项目工程根目录的入口；若要操作真实引擎，可新建绑定原工程的项目。项目 ZIP 不包含 WebUI 模型、LoRA 或整套安装，不能替代完整游戏工程备份。

### 13.3 更新代码

先保存浏览器草稿，按项目保存资料包和工程快照，再正常停止服务。需要整套本机回退副本时，在停止后复制运行数据根（默认 `.workbench/`，或自定义 WORKBENCH_DATA），保留原工程和外部快照目录；不要只复制运行中数据库的单个文件。副本含私有数据及加密凭据，按私有备份保存。

随后更新源码与锁定依赖并重新构建。当前有启动时兼容迁移，但尚无安装包级自动备份、版本回退和迁移失败恢复向导；首次升级建议先在独立副本验证。把旧代码直接放回已升级数据库旁边不能保证兼容，不要删除数据库处理问题。

Windows 保存的 Key 与当前用户保护上下文有关，换电脑或账户不保证能解密，重新授权/配置是正常迁移步骤。Suno/Codex 身份与浏览器草稿也不会因复制工程自动迁移。

服务重启后，未结束对话会标记为中断，正在提交但结果不明的音乐记录会进入待核对状态；不会自动重发收费任务。不要用删除数据库的方式解决启动或显示问题。

## 14. 推荐的一次工作流程

| 阶段 | 主要操作 | 应留下的结果 |
| --- | --- | --- |
| 明确方向 | 保存总纲，与负责人讨论约束 | 一份明确范围的设计草稿 |
| 采用设计 | 人工审阅并保存正式设计 | 有版本号的设计依据 |
| 安排工作 | 创建任务，建立依赖和设计关联 | 可逐项核对的交付与验收条件 |
| 生成与编辑 | 导入/编辑资产，审阅音乐方案，按需确认收费生成 | 可追溯的候选文件与版本 |
| 验证交付 | 人工检查内容，在引擎中运行或重开验证 | 真实验收依据，或明确的受阻原因 |
| 记录与备份 | 更新任务、会话记忆，检查执行详情，导出项目 | 可继续工作的项目备份及独立工程备份 |

这种流程让负责人能够根据记录解释进度，也便于你发现“已经讨论”“已经保存”“已经执行”“已经验收”之间的差别。

## 15. 常见问题

| 现象 | 建议处理 |
| --- | --- |
| 页面显示无法连接本地工作台 | 确认服务已启动，访问 8765；查看启动终端或 所选数据目录下的 `logs/server.启动编号.error.log` |
| F5 提示端口被占用 | 先停止已有的一键启动或调试实例，再选择一种方式运行 |
| F5 找不到 Python 或 npm | 完成首次环境安装，确认项目 `.venv` 存在；Node.js 加入 PATH 后重开 VS Code |
| 改了前端但主页面没变化 | 使用 5173 热更新页面，或重新构建并刷新 8765 页面 |
| Codex 已登录，但没有回复 | 核对模型、账号权限与额度，再查看工具核验及执行详情；登录成功不是推理验收 |
| 获取模型列表成功，仍无法使用模型 | 核对当前会话模型 ID 和模型能力；目录可见不等于推理或视觉验证通过 |
| AI 没有保存文档或任务 | 检查是否在讨论模式；执行后还应检查真实工具记录与对应工作区 |
| 草稿存在，但 AI 似乎没读到修改 | 点击保存总纲、保存新版本或保存设置；浏览器草稿尚未成为项目资料 |
| 文档提交提示版本冲突 | 先保留草稿，对照当前项目版本处理差异，再提交，避免直接覆盖 |
| 任务无法标记完成 | 检查前置依赖、设计版本复核和验收依据 |
| 材质修改提示目标不一致或版本变化 | 重新扫描并选择工程内资产，重新读取属性；不要混用上传副本和原工程目标 |
| 音乐显示未授权 | 检查原版 Skill 与 Node.js，完成网页授权后再次核验 |
| 图片或音乐超时、结果未知 | 先核对执行记录及供应商结果，不要立即反复点击收费按钮 |
| 原项目似乎消失 | 确认是否切换了项目或 `WORKBENCH_DATA`；独立调试数据与原工作区不会自动合并 |
| 复制或归档后找不到会话 | 核对项目和负责人；勾选“已归档”查看历史会话 |

本版仅用于受信任的本机单用户环境。不要将服务端口公开到互联网；也不要在公开 Issue、截图或共享备份中暴露密钥、一次性授权链接和真实私有工程。源码使用 MIT 许可证，模型服务、音乐服务、引擎与资产的使用权分别遵循各自规则。

## 17. AI 与 Blender 角色建模

进入“角色建模”，让左侧专职负责人保存参数方案，审阅后点击本机生成。支持比例、配色、服装、发型与配件调整；产出 GLB、可编辑 Blender 源文件和预览图。每次修改派生新方案，原文件保留。未自动绑定或进行引擎验收。完整步骤、参数和故障处理见 [Blender 建模指南](BLENDER_GUIDE.md)。

## 18. 接续已有游戏项目

点击左侧“接入已有游戏”，输入工程文件夹，扫描后选择设计资料并接入。工作台会原位登记分类资产、保留文档快照并生成带来源的现状摘要。项目负责人可在只读模式下继续核对原代码；不会把原文声明自动计入完成或运行验收。重新扫描可发现新增、变化和缺失文件。完整范围与限制见 [已有项目接入指南](EXISTING_PROJECT_GUIDE.md)。

## 19. Tripo 云端建模

进入“角色建模 → Tripo · 云端生成”，配置 Tripo API Key 和区域，核验余额。可让左侧负责人保存方案，审阅后手动确认上传与积分；服务成功后查询并下载 GLB 纳入项目。保存方案不调用收费生成，未知结果不会自动重提。完整步骤与验证边界见 [Tripo 指南](TRIPO_GUIDE.md)。

## 20. 账户额度、完整工程快照与 GitHub

“账户额度”按服务显示 Codex 共享额度、Suno.cn/Tripo 积分和 DeepSeek 余额，点击后只读查询。失败或过期值明确标记，未知不会显示为零；OpenAI API 本版提供官方账单入口，不估算现金余额。

“项目留存”支持命名检查点、里程碑与发布前快照。先保存并暂停工程写入，再保存完整过滤工程和工作台资料；用 SHA-256 核对，恢复至独立新目录。GitHub 从冻结快照生成可审阅的文件清单，确认权利和公开范围后上传新分支，大文件使用 LFS；不会改动原工程 Git 或覆盖主分支。

留存范围、排除项、缓存时效、真实验收边界、异地副本建议与恢复限制，见 [账户额度与项目留存指南](PROJECT_RETENTION_GUIDE.md)。

## 21. 桌面应用与当前版本的区别

当前交付是本机服务加浏览器界面，尚无独立安装器、自动更新或桌面进程托管。双击脚本、发布 ZIP 和 VS Code F5 都属于现有运行入口。

现有功能适合开始 Windows 内测应用封装，但仍需处理自带 Python、数据与安装目录分离、工具桥、后台退出和升级恢复。封装不会自动补齐 Unity 许可证、付费 API 权限、通用电脑操作或游戏验收。评估结论与按阶段验证的计划见 [应用封装评估](PROGRESS_AND_APP_READINESS_2026-10-26.md)。

## 22. Agent 全功能、整机与自动积分

展开对话中的“Agent 访问与积分授权”，选择权限并明确确认后保存。执行模式下，全功能会话可发现 76 项业务动作；SUNO 与 Tripo 自动提交各自需要积分授权，关闭的通道只保留草稿和原有人工提交入口。Codex 整机开关另行确认，仅 Codex 生效，不能把积分开关当成系统级限制。

未保存选择不会生效。点击“撤销增强授权并停止当前调用”使旧作用域失效；已提交云端任务和已写入产出仍需到对应工作区核对。复制和恢复不会继承增强授权。音乐/Tripo 页保存的默认模型用于新方案，已有方案保留原模型。完整步骤、权限矩阵、来源和验收边界见 [授权与功能互通指南](AGENT_ACCESS_GUIDE.md)。


## 23. 多文件夹与项目整理瘦身（0.11）

接入向导可填写一个主工程及每行一个附加目录，最多8个；已有项目在总览添加来源。总览的“让当前AI分析与制定整理方案”使用左侧已选模型，刷新索引和审计后强制讨论模式，保留未发送草稿。分析会计入所选服务用量。

展开“项目整理与可恢复瘦身”查看体积、较大文件、重复样本与可归档缓存。关闭编辑器、审阅具体文件并确认后，先创建校验备份再移出原文件；恢复只补缺失，不覆盖新内容。游戏资源的物理重排或无引用删除尚未实现。多来源快照、备份空间、限额与步骤见 [专门指南](MULTI_SOURCE_AND_MAINTENANCE_GUIDE.md)。

## 24. 作业、音乐资产与交付验收（0.12）

在“作业中心”查看八类创作/管理执行，按类型、状态和标题筛选。详情同时显示统一状态与原始状态；“查询完成”只说明查到了结果，生成任务可能仍在运行。查询和免费接入进入持久队列，页面每2.5秒刷新本机记录，远端查询由用户或获授权的 Agent 明确发起。

成功 SUNO 音轨可在音乐页或作业详情中确认“下载纳入资产”。工作台重新查询已知音轨、校验公网下载文件后登记，重复接入复用原资产；不重新生成、转换或消耗音乐生成积分。支持 MP3/WAV，单文件最多50 MiB、时长不超过1小时；声音质量、版权和引擎适用性仍需人工确认。

在任务“编辑与关联”选择交付资产，或从作业产出选择目标任务，核对当前版本并重置为待执行。完成时审阅固定版本与哈希，填写新的验收依据。验收历史保留当时的来源和版本；资产改变后原任务及下游需要复核，采用新版也不会自动验收。原导入文件的元数据与后续编辑版本分开展示。

重启只自动接续已有编号的查询；进行中的文件接入需人工核对/重新操作，不自动重放收费生成。资料恢复保存历史但不继承会话权限，未完成队列不会作为新任务自动执行。完整流程、格式限制及截图见 [作业与资产交付指南](JOBS_AND_DELIVERY_GUIDE.md)。

## 25. 上下文、Markdown 留存与任务驱动创作（0.13）

在对话栏“上下文与 Markdown 留存”选择自动或精简模式，并预览当前资料覆盖。目录较大时减少正文与数量，原文、任务细节及早期交流仍可按需读取；字符统计不是模型token计费。

点击“管理项目记忆与 Markdown 留存”打开独立窗口，补充关键决定、Skill约定及工作流，保存为PROJECT_MEMORY.md、SKILLS.md、WORKFLOW.md三份项目草稿。每次新增一组，不覆盖旧记录；可在设计资料审阅修改，并下载最近保存组。Skill文件记录使用约定与出处，不是自动安装包或授权。AI整理按钮只追加请求到当前输入框，由用户确认后发送，不自动扣费或开启执行。

任务卡新增“创作方案与候选交付”，可保存四类免费方案、进入原作业继续处理，并自动汇集已登记产出。核对后明确采用当前版本，任务重置待执行，再独立验收。任务与作业自动刷新采用分类指纹/条件请求，减少重复传输；没有后台高频查询云服务。完整操作、限制及截图见 [上下文与任务创作指南](CONTEXT_AND_TASK_WORKFLOW_GUIDE.md)。

## 26. 运行诊断、实例及数据目录（0.14）

不选项目也能打开“运行诊断”。默认只发现文件和版本，点击含写入检测的按钮才创建并清理本次临时文件。核心条件与可选创作工具分开展示，文件发现不等于真实连接/生成已验收；诊断不自动安装或修复。

启动器核对源码、数据目录和版本，停止前再次核对实例。自定义端口和数据目录后，停止使用相同参数；切换目录不会自动搬迁旧数据库。同一数据目录由系统独占，另一个端口不能重新初始化它；不要删除锁文件绕过运行中的服务。0.13及以前无身份字段，先确认原窗口与端口，再按指南显式正常停止。完整命令与升级说明见 [运行与诊断指南](RUNTIME_AND_DIAGNOSTICS_GUIDE.md)。当前产品状态及下一开发顺序见 [10月27日报告](PROJECT_STATUS_AND_PLAN_2026-10-27.md)。
